# Decisions: languages

English, French and Spanish, and the switch between them. How it works is in `docs/i18n.md`.

## 2026-10-07

**The site is in English, French and Spanish, and English is what a visitor gets until they choose.**
Kevin asked for a French and a Spanish version, with one condition: English stays the main one, even for a Spanish browser on a Spanish connection, and the visitor has to set the language explicitly. So nothing is detected. The language is in the URL (`/fr/...`, `/es/...`, English with no prefix): a link sent to a client opens in the right language, and nothing is saved in the browser, which keeps the privacy page true. Rejected: guessing from the browser or the IP, which he ruled out; remembering the choice in `localStorage`, which the privacy page would have had to declare and which a shared link would not carry; a library (`react-i18next`), for three typed objects and a context. How it is built is in `docs/i18n.md`.

**The language switch shows codes, not flags, and sits beside the theme switch.**
Kevin's question was where to put the flags. The answer he accepted: `EN` / `FR` / `ES` in the monospace of the slash labels, on one button that opens the list of three, just before the theme switch (the two settings of the site together, Contact still last and alone in red), and visible in the top bar on a phone, since a visitor who does not read English must find it without opening the menu. The footer repeats it as a plain line. Flags were set aside because a flag is a country: Spain's for a Mexican client, France's for a Belgian one, and two candidates for English. Three flags side by side would not have fitted the desktop row at 768px either.

**All copy moved out of the components, into one file per language.**
Until now every sentence was hard-coded where it was rendered. Three languages made that impossible to keep in step, so the sentences are in `src/i18n/messages/`, and the French and Spanish files are typed against the English one: a missing sentence fails the build. Lists keep their order and icons in the component and name each entry by a key. Rejected: translations written beside each English string in the components and data files, which spreads one language over thirty files. The French says "vous" and the Spanish "tú"; both translations are Claude's and are listed in `to-confirm.md` for Kevin to read.

**Chrome does not offer to translate the site.**
Kevin did not want Google's translation pop-up over his pages. `index.html` carries `<meta name="google" content="notranslate">`, which stops the browser from offering it by itself. Rejected: `translate="no"` on `<html>`, which also blocks a translation the visitor asks for from the browser menu, and some clients read French or Spanish before English. (Written when the site was in English only; later the same day it gained its own French and Spanish, and the tag stays.)
