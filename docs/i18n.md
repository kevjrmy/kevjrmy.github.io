# Languages

The site is in English, French and Spanish. This file is how that works and what to keep in step.

## The rule

English is the main language. A visitor reads English until they choose another one: nothing is detected, not the browser's language and not the country. That is Kevin's decision (2026-10-07): a Spanish browser on a Spanish connection still opens the site in English.

## Where the language is

In the URL, and nowhere else. English has no prefix; the two others live under their code:

| Page | English | French | Spanish |
|------|---------|--------|---------|
| Home | `/` | `/fr` | `/es` |
| Services | `/services` | `/fr/services` | `/es/services` |

So a link sent to a French client opens in French, and nothing is saved in the browser (the privacy page stays true: `docs/content.md`, Privacy page).

`src/i18n/locales.ts` holds the list of languages and the three path helpers (`localeOf`, `basePath`, `localizePath`). `App.tsx` declares every page once and registers it under each language. `MainLayout` reads the language from the URL, provides it to the page, and sets `<html lang>`.

Page paths themselves are not translated: `/fr/services`, not `/fr/prestations`.

## Where the words are

One file per language in `src/i18n/messages/`: `en.ts`, `fr.ts`, `es.ts`.

- `en.ts` is the reference. `fr.ts` and `es.ts` are typed against it, so a key that is missing, or one too many, fails the build. The length of a list (the award facts, the privacy bullets) is the one thing the type does not check.
- A component reads its words with `const { t } = useLocale()` and then `t.services.h1`. No sentence is written in a component.
- What is not a sentence stays where it was: icons, links, years, the order of a list, brand and product names. A list in a component or in `src/data/` gives the order and the icons, and names each entry by an `id` that is its key in the messages.
- A sentence with a link in the middle (the terms page) is cut around the link: `before`, `link`, `after`.
- A sentence with a value in it is a function: `visitLabel: (title) => ...`.

Changing any copy means changing it in the three files, in the same change. Each file has the same sections, in the same order:

| Content | Section of the messages | Rendered by |
|---------|-------------------------|-------------|
| Navigation labels, mobile menu tagline | `header` | `components/Header` |
| Footer links | `footer` | `components/Footer` |

| Terminal: role, closing prompt | `cli` | `components/Home/CliPrompt` |
| Home stack strip: titles and links | `homeStack` | `components/Home/Stack` |
| Homepage services teaser | `homeServices` | `components/Home/Services` |
| Selected work: heading, labels | `works` | `components/Home/FeaturedWorks` |
| Startup Weekend award: text, facts, photo captions | `award` | `components/Home/StartupWeekend` |

Not in the messages, because they are names and not sentences: the tools of both stacks (`src/data/stack.ts`), project titles and badges (`src/data/projects.ts`), the tool tags and logos of the journey (`src/pages/ai/Ai.tsx`), and the contact details (below).

## Links

A link to a page of the site is `Link` from `@/i18n/LocaleLink`, not from `react-router-dom`. It is written without a language (`to="/services"`) and leads to the page in the language being read. The plain router `Link` is used only where the target language is chosen on purpose: the language switch and the footer's language line.

To test which page is shown, compare with `basePath(pathname)`, not with `pathname`: on `/fr/about` the page is `/about`.

## The switch

`components/LanguageSwitch` is a button showing the code of the language being read (`EN`, `FR`, `ES`) that opens a list of the three. It sits just before the theme switch, in the three places the theme switch is: the desktop nav, beside the menu button on a phone, and in the menu sheet. The footer repeats the choice as a plain line (`English · Français · Español`).

- **Codes, not flags.** A flag is a country, and each of these languages is spoken in several; English would need a choice between two flags. Kevin's decision (2026-10-07).
- Each entry is a link to the same page, and the same `#anchor`, in that language.
- Switching language does not scroll and does not replay the page transition: `MainLayout` keys both on the page, not on the URL. The one exception is the hero terminal, which is typed again in the new language.

## Voice, per language

- **French**: the reader is "vous". "Stack" is feminine ("la stack classique"). Valencia is "Valence", with "en Espagne" where the English says Spain; the event keeps its name, "Techstars Startup Weekend Valencia". A space before `? ! : ;` and inside `« »` is written ` ` in the file, visibly, so the sign never starts a line on its own.
- **Spanish**: as written in Spain, and the reader is "tú". "Stack" is masculine ("el stack clásico"). "Portfolio", not "portafolio".
- In both: no em dash, as in English (`docs/content.md`, Voice), and "Claude Code" and "agents IA" / "agentes de IA", never a vague "IA" (`docs/content.md`, Positioning). Product names, the `/ai-agents` command of the headline, the `whoami` of the terminal and its four keys, and "Grand Prize" (it is what the certificate reads) are not translated.
- A person whose gender is not known is written without one: "un membre de l'équipe", "una persona del equipo", "Fesma, peintre et photographe".
- Longer words must still fit. The desktop nav holds five links, the two switches and Contact from 768px in all three languages, and a label that wraps in a narrow column gets a shorter wording (the classic stack's "Mise en ligne", "Hosting y despliegue").

## Adding a language

1. Add its code to `locales` and its name to `localeNames` in `src/i18n/locales.ts`.
2. Add `src/i18n/messages/<code>.ts`, typed `Messages`, and register it in `messages/index.ts`.
3. Check the header at 768px and the pages at 360px with the new labels.

## Limits

- All three languages are in the one JavaScript bundle. That is about 50 KB more than English alone (17 KB gzipped). Loading a language on demand would save it at the price of a wait on the first switch.
- Like every deep link on GitHub Pages, `/fr` and `/es` are answered with a 404 status around the working page (`docs/architecture.md`, Deep links). There are no `hreflang` links either. Both would come with prerendering.
- `index.html` keeps `<meta name="google" content="notranslate">`: the site now offers its own French and Spanish.
